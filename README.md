# HotMill — アルミニウム熱間可逆圧延シミュレータ

4段可逆式（4-High Reversing）アルミニウム熱間圧延機を、設備構造・圧延理論・操作系まで含めて
ブラウザ上で再現する単一ファイルアプリケーションです。`index.html` を開くだけで動作します
（three.js を unpkg から読み込むため、初回はネットワーク接続が必要です）。

## 0.5 バージョン（版数）の管理

画面左上、製品名の横に **`VER.x.y.z`** のバッジが出ます。押すか <kbd>V</kbd> で
**変更履歴**が開き、「どの版で・何が・どこに入ったか」が 1 画面で読めます。

| 桁 | 上げる条件 |
|---|---|
| **x** | 機構そのものの作り直し、座標系や設計の前提が変わる改修（`1.0.0` = 版数管理の起点） |
| **y** | 設備や機能の追加、図面の反映 |
| **z** | 不具合修正・数値の調整だけの更新 |

**更新の手順は 1 つだけです。** `index.html` の 0 節にある `VERSION.LOG` の**先頭に 1 件足す**
（`v` / `base` / `date` / `title` / `items`）。`items` の `w` には «どこで実装したか» ＝
主な関数・データ名を書きます。

`base` は **その版の作業を始めたコミット**（＝ 1 つ前の版の最後のコミット）です。
書く時点で必ず分かる値なので、あとから前の版へ書き足す必要がありません。
これで、画面の版数からその版の差分まで直接降りられます。

```bash
git log 0704131..33b11db   # VER.0.8.0 に入ったコミット（base .. 次の版の base）
git log 33b11db..HEAD      # 最新の版に入ったコミット
git diff 33b11db..HEAD     # 最新の版で何が変わったか
```

版数・日付・履歴の**真実は `VERSION` の 1 か所だけ**で、バッジ・履歴パネル・ブラウザのタブ名・
評価器はすべてそこを見ます。したがって「画面には新しい版が出ているのに中身が古い」という
食い違いが起きません（`tools/eval.mjs` がバッジの文字列と `VERSION.label` の一致、履歴の並び、
`base` の重複が無いことを検査します）。

### 最大圧延速度は独立した仕様ではない

`330 rpm ÷ 5.96 = 55.4 rpm`（ロール）× `π × 0.930 m` = **161.8 mpm**。
別に与えられていた「最大圧延速度 161 mpm」と一致します。つまり最高速度は
モータ最高回転数・減速比・ロール径から決まる従属値なので、`Drive.maxSpeed()` で導出しています。
ロールを研削して径が小さくなれば最高速度も下がります（Φ885 では 154 mpm）。

直流機は **基底回転数 150 rpm までが定トルク、そこから 330 rpm までが定出力**です。
これを駆動包絡線としてそのままモデル化しました。

- ロール軸最大トルク = `(1,900 kW × 2) ÷ (150 rpm) × 5.96` ≒ **1,442 kN·m**
- 所要トルクが大きいパスほど出せる速度が下がる（定出力域では速度と反比例）

実際、巻取パスでは速度上限が 111 → 89 mpm と低下していく挙動が出ます。
運転時のリミッタもこの包絡線で動くため、圧延荷重が上がると自動的に減速します。

### テーブル長が非対称な理由

**入側 121.8 m は「巻取直前のパスで板が載りきる長さ」そのものです。**
呼び厚 406（面削後 382 mm）× 長さ 4,200 mm のスラブを 8 mm まで圧延すると板長は約 200 m に達し、
テーブルには載りません。逆算すると、テーブル上で往復できる最薄は入側 121.8 m ÷ 伸び ≒ 14.5 mm。
そこから最終 1 パスで 8 mm へ落として巻き取る、という構成になります。
実際に生成されるスケジュールでも第 8 パス後の板長は **110.6 m** で、入側テーブル長にちょうど収まります。
つまり巻取リールは付加設備ではなく、この板厚を作るための必須設備です。

### ロール研削とパスライン調整装置

ロールは研削のたびに径が小さくなります（WR Φ930→Φ885、BUR Φ1430→Φ1350）。
下ワークロール上面をパスラインに保つには、減径ぶん（最大 62.5 mm）を下バックアップロール

ソールプレートの上に、ソールプレートはピット床の上に載ります（以前はハウジングがソール
プレートを貫き、下端がピット床より 35 mm 下にありました）。

### 材質（JIS 代表合金）

材質は `CONFIG.ALLOYS` に 1000〜7000 系の代表組成を持ち、サイドバーで選べます。

材質を変えると、圧延荷重・パス数・温度推移・端部欠陥（クロップ長）・反りがすべて変わります。

| A5052 Al-2.5Mg（既定） | 52 | 0.0060 | 0.12 | 380–520 | 300 | 1.4 | Mg 固溶で硬い。既定ロット（実機ロット: 560 mm・片面 15 面削・1,330 × 3,450 mm → 8 mm コイル、433 ℃）は実機と同じ 23 パスで通り、最大 3,687 t（最終パスの尻）で成立する |

炉出し温度スライダの範囲は選んだ合金の熱間域に自動で合わせます（範囲外の温度を選ばせない）。
温度依存性 b は Zener-Hollomon の活性化エネルギーから `d(ln σ)/dT ≒ Q/(nRT²)` で見ると
5000 系で 0.008 /K 程度ですが、指数形は低温側で過大になるため（sinh 形は低温で寝る）、
300 ℃ の公表値（5052 で 120〜170 MPa @ 10/s）に合うよう 0.006 に置いています。
それでも低温パスで主機が動力律速になり、最終パスの速度が下がる挙動が出ます。

### ラインの向き

`CONFIG.FLIP` が第1パスの進行方向を決めます。寸法はすべて「第1パスが +X」の正準向きで
記述し、`mirrorLayout()` が X 座標とパス方向をまとめて折り返します。個々の箇所で
符号を書き分けないので、入側／出側の左右反転は定数 1 個で切り替わります。

パスラインは**調整装置（ステップウェッジ）付き**の構成としています。圧延中は下ワークロール上面が
パスラインで固定され、圧下はすべて上側（油圧圧下シリンダ）で行います。

## 1-2. スラブ装入設備の配置

実機配置に合わせ、転倒機とその周辺（ピット炉・装入クレーン）は **入側テーブル A-8 / A-9 / B-1 の操作側**
（ライン中心から側方 3.8 m、転倒軸はミル中心から 33.0 m）に置いています。スラブはピット炉で立てたまま
加熱され、装入クレーンで吊り上げられて転倒機に立てかけられ、倒されたあと **トランスファークレーン** が
吊り上げてラインへ横移動し、A-9 テーブルに降ろされます。ラインへの移動は **テーブルローラによる送り出しでは
ありません**（縦送り・横送りローラは持ちません）。

工程は `CONFIG.SEQUENCE` の並びがそのまま定義になります（9 工程）。

| # | 工程 | 内容 |
|---|---|---|
| 1 | 蓋開 | ピット炉の蓋をスライドさせて開く |
| 2 | 吊上げ | 加熱済みスラブを立てたまま装入クレーンで炉から引き上げる |
| 3 | 横行 | トロリが転倒機まで横行する |
| 4 | 立てかけ | 転倒機の受け面へ降ろす（この時点でスラブは直立） |
| 5 | 転倒 | 転倒アームが 90° 倒し、ベッド面（＝パスライン高さ）に平置きにする |
| 6 | 送り | 転倒機ベッドのテーブルローラが `FEED_DX = 2,500 mm` だけ出側へ送り、続きの受取テーブル（同じテーブルローラ）へ渡す（下記「2 台のクレーンのフレームを分離した理由」） |
| 7 | 吊上げ | トランスファークレーンが待機位置からスラブの真上へ走行し、トングを降ろして爪で側面を掴み、受け面を越える高さ（パスライン上 1,700 mm）まで吊り上げる |

### 2 台のクレーンのフレームを分離した理由

装入クレーン（ピットクレーン）は立てたスラブ（最大 4,200 mm）を吊るため桁高さ 12.5 m の
背の高いフレームが要ります。トランスファークレーンは平置きの薄い板を 1.7 m 持ち上げるだけなので、
同じ高さのフレームを共用する理由がありません（共用させていた旧版は、桁からスラブまでのワイヤが
10 m 近く垂れ下がる不自然な絵になっていました）。

フレームを別にすると、今度は**転倒直後のスラブがピットクレーンの脚の内側にあり、低いフレームの
受け持ち域に届かない**という問題が出ます。低いフレームの Z スパンは転倒アームの占有域だけでなく
主テーブル架台（ロール胴端の外側、Z = ±1,545 mm）とも重ならない位置まで押し出す必要があり
（`tools/structure.mjs` のレイキャスト判定で実測）、その結果フレームは転倒軸から離れた位置にしか
置けません。そこで転倒後、**転倒機ベッドのテーブルローラが板を FEED_DX だけ出側へ送り**、その続きの
受取テーブル（同じテーブルローラ）へ渡してからトランスファークレーンが掴む、という 2 段構えにしています。

送り機構をプッシャではなくテーブルローラにしているのは、転倒機ベッドと受取先が **1 本の搬送ライン**
だからです。ローラ仕様は `CONFIG.SUPPLY.ROLLER` の 1 か所に置き、形状は本線と同じ `Parts.tableRoll()`
を胴長と軸端長だけ変えて使います。回転は角度を積算せず、送り距離から転がり条件 θ = −距離 / 半径 で
毎フレーム決めるので、コマ落ちや巻き戻しがあっても板とローラがずれません（`tools/layouttrace.mjs`
がすべり量を実測して 20 mm 未満であることを確認）。

### トングの構造

トングは図面（最大巾 2,680 / ロッド芯間 1,525 / 全高 3,355 / 爪 560）に合わせた挟み込み式です。
マスト下端の**中心ピン**に 2 本のアームを吊り、**肘ピン**をシリンダで押し引きすると両アームが
中心ピンまわりに逆向きに回って爪が閉じます。爪はスラブの**側面（板厚の面）**を掴むだけで下へは
回り込まないので、テーブルローラに載ったままの板をそのまま持ち上げられます。爪先はローラ上面より
`JAW_LIFT = 60 mm` 上で止め、ローラの胴には当てません。

油圧シリンダは**受け梁の両端に鉛直に据え**、胴の中ほどを梁のバンドが抱き、ロッドが下向きに出て
アームの**ロッドピン**へ届きます。ロッドピンはアームと一体なので、アームの回転をそのまま掛ければ
現在位置が決まり、シリンダ本体は梁に固定されたままなので、**ロッドの出代は 2 点間の距離として
自然に決まります**（別に持たせて食い違う、ということが起きません）。

開閉はアームの回転角だけで表しています。爪の内面は中心ピンから半径 R の円周上を動くので、
目標の開き幅に対する角度は `asin` で一意に決まり、開き量・爪先高さ・ロッドピン位置・シリンダの
出代がすべてこの 1 つの角度から出ます。

**簡略化している点:** 図面では «中心ピンから V に開く上リンク» と «そこにピンで繋がる湾曲した
爪アーム» が別部材で、左右をたすき掛けのタイバーが結んでいます。ここでは上リンクと爪アームを
**中心ピンまわりに回る 1 個の剛体**として扱い、たすき掛けのタイバーは省いています（実機の 4 節
リンクを毎フレーム数値解法で解く代わりに、姿勢が一意で食い違わないことを取りました）。
シルエットとシリンダの動きは図面どおりです。

この «全高 3,355 mm のトングを吊る» という条件が、トランスファークレーンの桁高さを決めています。
最も高くなるのは最小幅スラブ（900 mm）を掴んだとき（アームが立つぶん中心ピンが爪先から遠のく）で、
爪先 2,660 → 中心ピン 4,293 → 吊りピン 6,398 → 吊りビーム上面 +420 → ロープ最小 300 と積み上がり、
桁高さは 7,500 mm 必要でした（ピットクレーンの 12,500 mm よりは十分低い）。

### 成立条件（自動検査している項目）

- 降ろしたスラブ（最大 4,200 mm）が A-9 テーブルの範囲に収まり、3 本以上のローラに載る
- 転倒機ベッド・受取テーブルのローラ上面がパスラインに一致し、受取テーブルは転倒アームの回転半径の外にある
- ローラの回転が送り量と一致する（転がり条件・すべり < 20 mm）、送り量が `FEED_DX` に一致する
- 横移動時のスラブ底面（パスライン上 1,700 mm）が転倒機の受け面（1,510 mm）より上
- 全開のトング（外面 1,340 mm）が転倒アームのサイドレール内面（1,390 mm）の内側に収まり、
  爪内面（1,140 mm）は最大幅スラブの半幅（1,100 mm）より外にある（＝板を跨げる）
- 2 台のクレーンの桁が待機時に重ならない（桁間 ≥ 760 + 最大スラブ長/2）
- 装入の全工程でスラブが装入設備（受取テーブル・両クレーンを含む）に食い込まない（`tools/supplytrace.mjs`、分離軸判定）
- 静的構造物どうしが食い込まない・浮いていない（`tools/structure.mjs`）。トランスファークレーンの
  低いフレームを主テーブル架台・転倒装置とぶつからない位置まで押し出したのはこの検査で確定させた
- **トング（可動部）が転倒アーム・受取テーブルと食い込まない**（`tools/tongtrace.mjs`）。
  既存の検査は «静的部材どうし» と «スラブと設備» しか見ておらず、«動く設備と他の設備» が
  抜けていた。爪を下ろす先がローラと側枠の間なので、この穴は塞いでおく必要がある
- **クロップ屑の払い出しが機械として成立する**（`tools/scraptrace.mjs`）。下台の全ストロークで
  固定ストリッパシュートが下台を貫かないこと、受け開口がテーブル架台の足元を掘っていないこと、
  先端・後端の屑が段階どおりに進んで同じ屑箱に収まることを機械判定する

### 転倒装置とスラブの干渉を無くした構造

以前は転倒軸（Φ560）の軸心がベッド面（パスライン）にあり、寝かせた板にも立てた板にも
軸が 280 mm 食い込み、アームには床下 1.5 m まで潜る «支持脚» が付いていました。現在は

- 転倒軸をベッド面より **330 mm 下**（軸半径 280 + 余裕 50）に置く。寝かせたときベッド面は
  パスライン、立てたときの受け面は軸から 330 mm 離れた平面になる
- 立てた板は受け面に寄りかかり、底面は **リップ**（寝かせたときの立ち上がり板）に載る。
  リップは軸の真上（y ≥ 320）から立つので回転しても軸に当たらない
- サイドレールは軸受（Φ940）の外側から始め、軸ハブ（Φ640）で軸を抱く
- 寝かせたアームは床上の受け台に載る。基部・軸受台・転倒シリンダの受けも床上

転倒中の板の位置は、アームのローカル系で板中心 (L/2, 330 + t/2) を軸まわりに回すだけで
決まり、立位・倒位の両端で立てかけ位置・搬送位置に一致します。
装入の全工程でスラブが装入設備に食い込まないことは `tools/supplytrace.mjs`
（回転する板と設備の三角形の分離軸判定）で確認しています。

**ラインへの移載はローラ送りではなくトランスファークレーンです。** 以前は昇降式の横送りローラで
ラインへ渡していましたが（ジオメトリに昇降ステムが含まれて回転で振れる、回転向きがラインの向きの
反転を考慮していない、という不整合があった）、この機構は撤去しました。現在テーブルローラが担うのは
**転倒機ベッド上と受取テーブルまでのライン方向（X）の送りだけ**で、ライン中心（Z = 0）へ渡すのは
トングを持つトランスファークレーンです。

## 1-3. 出側仕上げ設備の動き

出側には、ミル中心から順に **サイドトリマー（5,875 mm）→ スリーロール（6,900 mm）→
巻取リール（8,350 mm）** が並び、さらに遠方（ワークロール出側から約 30.6 m）に
**75 mm クロップシャー**があります。距離が大きく違うのは役割が違うためで、
一体の設備ではありません。

| 設備 | いつ働くか | 何をするか |
|---|---|---|
| 75 mm クロップシャー | 板厚が 75 mm 以下になった最初のパス | 先端のワニ口・ラウンドを切り落とす。**上刃固定・下台上昇式**（板押え無し）で、1 カット 300〜500 mm を欠陥が消えるまで繰り返す。**出側のみ**に存在する |
| サイドトリマー | 最終パス（コイル仕上げ時） | 両耳を切り落として仕上げ幅にする。切った耳材はスクラップチョッパで細断される |
| スリーロール | 通板時 | 下2本・上1本で板を挟み、リールへの通板経路をつくる |
| 巻取リール | 最終パス（板厚 10 mm 以下） | マンドレルを拡張して先端を把持し、張力を掛けながら **外周に 1 枚ずつ** 巻き取る |
| 30 mm シャー | 板材の仕上げ（板厚 30 mm 以下） | J-3 テーブルの先（80.9 m）。下刃固定・上刃下降式（板押え付き）で、板を 9 m 定尺に切り分ける |
| パイラー | 板材の仕上げ（板厚 75 mm 以下） | 30 mm シャーの先（82.3〜92.3 m）。切り分けたシートを片持ちローラアームで受け、アームが左右へ開いてリフトテーブル上の山へ落とす。山が高くなるぶんテーブルが下がる |
| 板置き場（クレーン） | 板材の仕上げ（板厚 75 mm 超） | どちらのシャーでも切れないので J-3 末端で止め、クレーンで駆動側の板置き場へ降ろす |

### 仕上げ形態は板厚で決まる

目標板厚は 4〜150 mm で自由に設定でき、**10 mm 以下ならコイル、10 mm 超なら板材** と
自動で振り分けます（`Rolling.finishMode`）。板材はさらに板厚で行き先が決まります
（`FinishState.divider`）: **30 mm 以下は 30 mm シャー、75 mm 以下は 75 mm シャー**で 9 m 定尺に
切り分けてパイラーへ、**75 mm 超**は切れないので J-3 末端からクレーンで板置き場へ。切り分けは
«シャーの先（定尺 + 隙間）にシートが残っていない» ときだけ板を送り、切り離したシートはパイラーの
停止位置（または前のシートの手前）で止まって順に積まれます。板の尾端を含む最後のシートは切らずに
板そのものを送り、尾端の張り出し（舌）を保ったまま山に載ります。パススケジュールは板厚・板幅・材質から
その場で生成され、待機中の変更は «適用» を押さなくても即座に反映されます。
巻取中は圧延後の板がすべてコイル側へ行き、出側テーブルへは流れません
（以前は板メッシュが 3ロールを越えて出側テーブルにも描かれ、板がコイルと出側に二分して
見えていました。現在は板の入口 A（3ロール出側ローラ上）で打ち切り、そこから先は渡り板と
コイルだけが描かれます）。

**サイドトリマーはシャーではありません。** スタータイプのスクラップチョッパ付き
クイックオープン型で、円形刃（Φ510〜498、厚 40〜30 mm）が板を連続的に走間切断します。
このため刃は板の通過速度に同期して回転させ、断続的に落ちる動作にはしていません。
「クイックオープン」は非通板時に刃を素早く開いて板幅方向へ退避させる機構で、
モデルでも通板前に刃を開き、切断時のみ閉じる動きにしています。

**75 mm シャーは上刃固定・下台上昇式**です。板を載せた下台（下刃付きの昇降テーブル、
長さ 1,800 mm）ごと油圧で持ち上げ、固定上刃（刃先はパスライン上 90 mm）に押し当てて
剪断します。板押えはありません。上刃が固定なので架構は上刃ホルダを受ける高さだけで済み、
クロスヘッド上面はパスライン上 1.1 m に収まります（以前のアップカット構造は 5.6 m ありました）。
刃は実機仕様の **75 × 180 × 2500 mm（NS3C, Hs 65±3°）**、最大剪断力は **368 ton** です。

### 端部の欠陥長と複数カット

切り落とす量は先端の欠陥（ワニ口・舌・ラウンド）の長さから計画します。

```
欠陥長 D = 圧下率² × 材質係数 × (1 + 0.8·低温度合) × (3.0·板厚 + 0.30·板幅)
必要量  = D + 余裕 120 mm   →  1 カット 300〜500 mm に等分（端数切り上げ）
```

板厚 60 mm 換算で、全材質・全幅・熱間域の上限〜下限にわたり総切断長は **410〜2,400 mm**
（1 カット 300〜500 mm）になります。切り上げのぶん必要量より少し余分に切るので、
ワニ口の根元が残って 2 枚板になることがありません。切断は
STOP → ALIGN（端を刃からカット長だけ先に置く）→ CUT（下台上昇）→ RETURN → 払い出し
を、計画したカット数だけ繰り返します。払い出しは端で分かれます。

- **先端** … EJECT → RETRACT。端材は下台と一緒に持ち上がった高さから固定エプロンへ落ち着き、
  駆動側のプッシャで操作側のコンベアへ払い出され、パレットに積まれます
- **後端** … BEDDOWN → STRIP → BEDUP。端材は下台に載ったまま降り、下台のテーブルの通し溝を
  貫いて固定されたストリッパシュートに置き去りにされて上流側へ滑り落ち、ライン下の端材ピットへ
  入ります。傾斜コンベアがテーブル架台の下をくぐって駆動側へ運び、末端の端材箱へ落とします

### 定格 368 t が決める剪断応力

368 t は最大断面（板厚 75 mm × 刃長 2500 mm）を剪断する力なので、その裏にある剪断応力は

```
τ = 368 tf ÷ (75 × 2500 mm²) ≒ 19.2 MPa
```

熱間アルミの剪断強さとして妥当な値です。モデルはこの τ から実際の断面での必要剪断力を
逆算し（`Rolling.cropForce`）、切断のたびに表示します。板厚 75 mm × 巾 2350 mm（トリム前最大巾）
でも 346 t で定格内に収まることを自動検査しています。

### 構造の成立条件（自動検査している項目）

- 下台の行程（90 + 60 mm）で下刃先が固定上刃の刃先を越える（切り離せる）
- 固定上刃の刃先はパスライン上 90 mm で、最大板厚 75 mm を通す
- 剪断面を挟んで、下台（下刃）が上流側・固定上刃が下流側（＝端材が残る側）
- 上下刃のサイドクリアランスは 4 mm（板厚 75 mm の 5.3 %）
- 架構の最上部がパスライン上 1.5 m 以内（コンパクト）、板押えを持たない
- 下台は柱の内側の昇降ガイド柱に案内され、床上のシリンダ本体の中をロッドが伸縮する
- 1 カットは 300〜500 mm、総切断長は 300〜2,400 mm（板厚 60 mm・全材質・全幅・温度域）

### 動作 — 画面実測で直したこと（履歴）

動作は推測ではなく、**描画されている実体の座標を毎フレーム読み出すトレーサ**
（`tools/croptrace.mjs`）で観測して直しました。以下はアップカット構造だった当時の実測で、
切断位置・端材長・払い出しの順序に関する結論は現在の下台上昇式にも引き継いでいます。

| 実測された症状 | 原因 | 対策 |
|---|---|---|
| 切断位置が刃と 9.4 m ずれる | 起動条件が `slab.thickness`（＝**入側**厚）を見ていたため、判定が 1 パス遅れて先端がシャーを通り過ぎていた。しかも切断処理が «板端から一定量を削る» 実装で、刃の位置と無関係だった | 判定を **先端の実厚**（噛み込み中はロールギャップ）に変更し、**通板の途中で**引き金を引く。切断は必ず **刃の位置 (x = 30.6 m)** で行い、切り落とし長は «刃より先にある材料の長さ» として求める |
| 端材が出てこない／板が短くならない | 実際には動いていたが、シャーが 30.6 m 先で**全視点から画面外**だった。切り落としも 300 mm しかなく 31.9 m の板では見えない | 専用視点（`7` キー）を追加。端材長を実機に合わせて **800 mm** に |
| 端材の落下タイミングが合わない | 切断と同時に落下を始めており、刃はまだ上死点にいた | 端材は刃に切り離されたあと**エプロン上に残り**、押え解放 → プッシャで払い出し → エプロン端で落下、という順序にした |
| 描画と論理の板長が 1.6 m ずれる | 端部の張り出し（舌・ワニ口）を **全長に比例**させていたため、31 m の板で 800 mm の舌が出ていた | 張り出しは板厚と板幅で決まる量（`0.8·t + 0.06·w` に圧下率を掛ける）に変更し、描画と物理で同じ式を参照させた |

現在の下台上昇式での 1 サイクル（A5052・板厚 50.3 mm での実測）:

```
STOP    先端がシャー手前で減速開始
ALIGN   先端を刃から 350 mm 先へ置く（±5 mm）
CUT     下台が上昇、板上面が上刃に当たり板厚の半分まで食い込んだところで切り離し
        切断位置 x = 刃の位置ちょうど / 端材 350 mm / 剪断力 148 t（定格 368 t）
RETURN  下台が降りる。端材は持ち上がった高さからエプロンへ落ち着く
EJECT   プッシャ面 −1900 → +1450 mm（端材は面に触れてから動き出す）
DROP    エプロン端 Z=2200 で落下 → コンベア → パレット（RETRACT でプッシャが戻ってから次のカットへ）
        ※後端のカットでは EJECT の代わりに BEDDOWN → STRIP → BEDUP（シュート → ピット → 傾斜コンベア → 端材箱）
ALIGN…  2・3 カット目（計画 3 カット × 350 mm ＝ 欠陥長 930 + 余裕 120 を切り上げ）
DONE    パス再開
```

### 屑の落ち方（エプロンを持たない理由）

刃の出側にはエプロンを置いていません。切った屑をその場で**テーブルロールの下へ落とす**ためです。
先端カットでは屑は支えを失って開口へ落ち、後端カットでは下台の上に残るのでシュートで移します。
どちらも受け面（傾斜コンベアのデッキ）に着床してから操作側へ運ばれ、末端で屑箱へ落ちます。
コンベアの桟は屑が載っている間だけ送られます。複数の屑が同時に搬送中でもかまいません。

出側へ «滑らせて» 出す案は採れません。下台の刃物台が正準 X −197〜+118 を上下に掃くので、
その回廊に固定のシュートを置けないからです（実測）。後端の屑を上流側へ落とすのはこのためです。

### 屑は切断時の形を保つ

端部の張り出し（舌＝幅中央が伸びる／ワニ口＝表裏が開く）は `Rolling.endOffset` の 1 式で、
板（`SlabView`）・端材・シートのすべてがこれを参照します。切り離した端材は
`Parts.plateSegment` が **切断時の形を頂点に焼き込んだ個別メッシュ**なので、板端の変形が
そのまま端材に残ります。刃が張り出しの途中にあるときは、板端はその位置で平らに打ち切られ
（`SlabState.cut`）、残りの張り出しは次のカットへ持ち越されます。したがって 1 カット目の端材は
舌の先端、2 カット目は舌の根元を切った形（切断面と切断面に挟まれた片）、最後は健全部まで
切り込んだ平らな片になります。切断面の位置は «健全端からの残り長さ» で持つので、板が動いても
一緒に動きます。

### 端材と体積収支

切り落とした端材のうち、**張り出し（舌・ワニ口）は形状のひずみなので板長としては減りません**。
板長として減るのは健全部だけで、既定条件（A3003、2 カット × 400 mm、欠陥長 ≈ 665 mm）では
800 − 665 ≈ 135 mm。これが最終体積差 **−0.44 %** の全量で、
`135 × 50.3 × 1500 ÷ (382 × 1500 × 4200) ≈ 0.42 %` と整合します。
材質や幅、温度で欠陥長が変わればカット数も体積差も変わります（A5052 では 3 カット × 350 mm）。

**巻取リールは 4セグメント・コラプシブルウェッジ式**です。マンドレルはウェッジ芯の上に
4 枚の円環扇形セグメント（外径 Φ610、肉厚 95、隙間 26 mm）が乗り、先端が 3ロールの手前
3 m に来たら **半径方向に 30 mm 拡張**（0.8 s）します。マンドレルは拡張・縮小するだけで
**板を掴む機構を持ちません**。巻き終えて（コイルを抜くときに）縮小して解放します。
セグメントは各自の二等分線方向に動くので、外接径の減少は 2 × 30 × cos45° ≒ 42 mm です。

### ベルトラッパー（巻き始め）

マンドレルが板を掴まない以上、**巻き始めを作るのはベルトラッパー**です。3 本のラッパーロール
が揺動アームに載り、その外側にベルトが掛かります。ロールが内側へ閉じるとベルトが
マンドレル外周に沿い、先端はベルトとマンドレルの間に入って摩擦で連れ回されます。
数巻きしてコイルが自分で形を保てるようになったらアームが開き、ベルトは離れます。

**常設の設備**です。使わないときは退避位置へ振り上げるだけで、消えることはありません
（初期の実装は «巻き付けている間だけ現れて終わると消える» もので、設備としては存在して
いませんでした）。

機構は 2 段になっています。

1. **各ロールはキャリッジ上の «接線方向の支点» に付いた短い剛体アーム**に載り、
   コイルが太るぶんだけ外へ逃げる（1 周ごとの段にも追従する）
2. **キャリッジそのものが 1 本の振り軸まわりに 55° 振れて**、ロール・アーム・ベルトを
   まとめて上へ退避する

②が要る理由は測って分かりました。可逆圧延機なので**板はどのパスでもリールの下（パスライン）を
通ります**。巻き付けの位置は «板の入口の直後» ＝ マンドレルの下側なので、そこから半径方向へ
開くだけではロールがパスラインまで下がり、`interfere.mjs` が **最大 443.7 mm の食い込み**を
検出しました。板の通り道（パスライン 900 + 最大板厚）を空けるには、まとめて振り上げるしか
ありません。

| 諸元 | 値 | 備考 |
|---|---|---|
| ラッパーロール | Φ240 × 面長 1,800、3 本 | 極角 212 / 300 / 25°（閉じたとき。真上が 90°） |
| 揺動アーム | 接線方向へ 700 mm の支点、アーム長 700 | **長さの変わらない剛体**。閉じたときアームはマンドレルに接し、開くほど遠ざかる |
| キャリッジ | 振り軸はリール中心から (−1,900, +200)、退避角 55° | ミルと反対側。そこだけ床も上空も空いている |
| ロール中心半径 | 閉 425（＝マンドレル半径 305 + ロール半径 120）／ 退避 1,389〜2,138 | 退避はロール面が最大コイル Φ1,900 の外 |
| ベルト | 厚 18、面長 1,800 | 3 本のロールに掛かる帯（円弧 + 共通外接線）を毎フレーム作る |
| 架台 | 振り軸 + 駆動側の柱 1 本 + 振れ止め | 床へ降ろすのは**駆動側だけ**（操作側の床はコイルカーの通り道） |

- アームは剛体なので、置きたい半径 r を決めれば揺動角が決まります（`|C|² = |P|² + L² + 2L(P·u)`
  を u について解く。`Wrapper.phiFor`）。支点を**接線上**に置くのが要点で、こうすると
  «閉じたときアームがマンドレルに接し、開くほど遠ざかる» 形になり、腕が芯を横切りません。
  `wraptrace.mjs` が全工程でアーム長が 700 mm から 1 mm も動かないことを見ています
- 退避は**揺動角で補間**します。半径で補間すると、円の上では同じ半径が 2 回現れるため
  «別の枝» に乗って腕が芯へ回り込みます
- 架台の Z は «コイルカーの走行域（±1,075）より外、テーブル架台（±1,325）より内» の
  200 mm の帯に収めています。操作側の床にはコイルカーが走るので、柱は駆動側だけです
- 順序は «拡張 → ベルトを閉じる → 先端が入る → 巻き付く → 3 巻き後に開く»。
  «閉じ切ってから通板» でなければ巻き始められないので、`coiltrace.mjs` が
  巻き付き開始時の閉じ度が 1.0 であることを検査している
- ロールは押えコロと同じく、**その極角でのコイルの実半径**（1 周ごとの段を含む）に当てる。
  平均半径に当てると 1 板厚ぶん浮くので、検査は隙間 3 mm 未満を要求する
- 旧版はマンドレルが先端を «把持» する実装で、実機に無い機構だった（板の挙動が不自然だった）
**駆動側に主軸受、その背後に減速機と電動機を同軸で並べ、操作側はアウトボードベアリング**という
片持ち構成で、操作側はコイルを抜き取れるよう開いた柱だけの構造です。
実機は鉄板で囲われた箱ではないので、モデルでも囲いは設けていません。

### コイルカー（巻き終えたコイルの払い出し）

リールは片持ち構成で、**操作側はアウトボードベアリングの柱 2 本だけの開放構造**（コイル抜き取り側）
です。巻取が終わると、リール真下のコイルカーが受け台を上げてコイル外周に当て、マンドレルを
縮小してから、その柱間（内法 760 mm）を通して**軸方向（操作側）へ 6 m 抜き取り**、降ろします。

- 受け台の上昇端は固定ストロークではなく、**コイル外周がデッキに載る高さ**
  （マンドレル芯 − コイル半径）から逆算する。コイル径は巻取結果で変わるので、
  固定ストロークにすると浮くかめり込む
- マンドレルは **カーが受けてから** 縮小する（先に縮めるとコイルが落ちる）。
  `coiltrace.mjs` が工程の順序（APPROACH → LIFT → STRIP → CARRY → SET → REST）を検査する
- **待機はリール下ではなく搬出位置**。出側テーブルはリールの «先» まで続くので、
  圧延中はリール下を板が通る。そこで待つとカーが板と当たる（`tools/interfere.mjs` が
  176 mm の食い込みとして検出した）。巻き終えてから APPROACH で入ってくる
- **出側テーブルはリールの手前で終わる**。以前は «ﾃﾞﾌﾟﾚｯｼﾝｸﾞ» 区分としてリール下に
  ローラ 2 本があり、コイルカーが入る余地が無かった（ローラ間の隙間は 368 mm しかない）

### クロップ屑の払い出し（入側・出側 → ラインの下の受け → 傾斜コンベア → OS の屑箱）

屑は必ず «刃を挟んで切る端の側» に落ちます。先端カットの屑は刃の**出側**に、後端カットの屑は
**ミル側 —— 下刃を載せた昇降下台の上**に残ります。以前はこれを 2 系統（先端＝エプロン＋
プッシャで OS へ、後端＝シュートで DS へ）に分けていましたが、**1 系統に統一**しました。
エプロン・プッシャ・ローラコンベア・パレットは撤去しています。

受けの開口は、シャーまわりで «床に着いているもの» を実測して決めました
（正準 X ＝ シャー中心から下流が +）。

| 部材 | 正準 X | Z |
|---|---|---|
| 昇降下台（掃く範囲） | −717 〜 +118 | ±1,570 |
| 下台の昇降シリンダ | −397 ±180 | ±1,500 ±180 |
| 下台の昇降ガイド柱 | −672〜−522 / −272〜−122 | ±1,750 ±75 |
| 75 mm シャーの柱 | −550 〜 +50 | ±2,400 ±380 |
| テーブル架台（床に接する足） | ローラごと | ±1,325 〜 ±1,765 |
| テーブルローラ（胴端 Φ281.6） | −1,175 と +800 | — |

⇒ **開口は 正準 X −1,030〜+650、Z −1,150〜+1,150**。刃の入側・出側の両方の真下に跨がり、
最大板巾 2,200 の屑が落ちる 2,300 mm を確保しつつ、床に着いているものを 1 つも掘りません。

- **広い傾斜スクラップコンベア（桟付き）**: 受け面そのものがデッキ（巾 1,600 mm）。
  ピット底（Z −1,050 でパスライン下 2,400 mm）から Z +9,000・パスライン上 72 mm まで、
  勾配 ≒14°。勾配は «床でふさいだ区間（Z 1,150〜2,900）を屑と桟が頭を打たずに通れる»
  ことで決まります。ふさいだ区間の下でテーブル架台とシャーの柱の足元をくぐります
- **屑箱**: 操作側の床上（Z 10,200、3,600 × 1,900 × 250 mm）

後端の屑だけは下台の上に載るので、**固定ストリッパシュート**で開口へ移します。フィンガは
下台のテーブルに空けた通し溝（Z = ±300 / ±700、溝幅 240 mm）を貫いて架構に固定されており、
下台が DROP（240 mm）だけ降りると屑だけがシュートに残ります。傾斜は
tan⁻¹(220 / 530) ≒ 22.5° で、鋼どうしの摩擦角（μ ≒ 0.25 → 14°）より大きいので自重で滑ります
（滑り出しの加速度 a = g(sin θ − μ cos θ)）。

シュートの下端とコンベアの頭部では、屑は **«支点を中心にこけてから落ちる»** 動きにしています。
重心が支点を過ぎた時点から回り始め、支点に当たる点が重心から後端へ移っていくので、板の後半は
最後まで支持面より上に居ます。平行に落とすと後半が支持面を突き抜けます（実測 517 mm）。

この構成は «固定部材（シュート）が可動部材（下台）を貫く» という、既存のどの検査も見て
いない形をしています。そこで `tools/scraptrace.mjs` で、**下台の全ストローク（上昇 +150 〜
下降 −240）でシュートが下台を貫かないこと**、開口が架台の足元を掘っていないこと、先端・後端の
屑がそれぞれ ONBED→CHUTE→CHUTE_TIP→PITFALL→CONVEY→DROP→REST ／ PITFALL→CONVEY→DROP→REST と
進んで同じ屑箱に収まること、搬送中に固定設備へ食い込まないことを機械判定しています。

### テーブル区分と E-1 / E-2（ミル直近の短胴ローラ）

ローラの配置は図面の「各テーブルローラ本数」（区分ごとの本数とピッチ表記）と区間長から
`Layout.section()` が導きます。区間長がピッチの合計とほぼ同じ区分（D で余り 5 mm、F で 15 mm、
H-1 で 0 mm）が多いので、収まるかどうかは **«ピッチの合計が区間長以下か» だけ**で判定します
（以前は «余りが胴端半径 + 20 mm 以上» を求めていたため、D・F・G-1・H-1 が軒並み等配へ落ちて
図面のピッチが消えていました）。余りが半ピッチを超える A-1 だけは、ミル側へ半ピッチで寄せて
隣の区分との継ぎ目が空きすぎないようにします。

**E-1 / E-2**（図面の 0〜2.5 m、ミルの直近）は他と造りが違います。

| 項目 | 値 |
|---|---|
| ローラ | Φ380 × 857L（SCM440）。中央は 1/100 の勾配で Φ377.1 |
| 本数 | 各 8 本 ＝ **4 段 × OS/DS 2 本** |
| 段の位置 | 正準 X 751 / 1,217 / 1,683 / 2,149（ピッチ 466） |
| 胴の外端 | Z = ±1,100（最大板巾 2,200 の半分）。内側の首は中央の 1 個の軸受で受ける |

段の位置は **ワークロール（Φ1,350）との軸間** と **D / F の 1 本目（正準 2,505、胴端 Φ281.6）**
との逃げで決まります。床はミルピットの開口なので脚は立てられず、ハウジングの柱間へ渡した
リブでローラの下をくぐらせて支持しています。周速を主テーブルと合わせるため、角速度は径の比
（281.6 / 380）で回します。これに伴い旧「ミル直下の敷板（エプロン）」は撤去し、下側の
ロールクーラントヘッダは E ローラの下をくぐる高さへ下げました。

配置が図面どおりかは画面上でも確かめられます。ツールバーの **「テーブル記号」**（<kbd>Z</kbd>）で
区分ごとに **記号バッジ**（区分名・本数・ピッチ表記）が出ます。バッジは «実際に並んだローラの
範囲の中央» に置くので、配置がずれていればバッジもずれて見えます。

### 1 枚ずつ巻き太るコイル

コイルは «外径が連続に太る円筒» ではなく、**外周に 1 枚ずつ板が巻かれて 1 周ごとに
板厚ぶん段になって太る**形で描きます（`CoilGeometry`）。

- 巻き数 = 板の周速 ÷ 巻き付け半径（今巻いている層の板厚中心）の積分。マンドレル 1 回転 = 1 巻
- 完成した層は内径 Φ610 〜 `r0 + 層数·h` の環（全周）
- 巻きかけの層は `r1 〜 r1 + h` の扇形で、板の入口から回転方向へ 2π × 端数だけ広がる。
  扇形の先端が **段** で、マンドレルが 1 回転するごとに入口へ戻ってきて次の層が始まる
- 板の入口 A（3ロール出側ローラ上の板厚中心）からコイルへは、巻き付け円への **接線** で入る。
  接点は円の下半分（**下巻き**: 板は下から入って奥→上→手前と回る）。コイルが太るほど
  渡り板の立ち上がり角は寝る（Φ610 で約 30°、Φ1,510 で約 16°）
- 尾端が入口 A を過ぎたら渡り板は A 側から縮み、接点に達したところで巻取完了

巻き数の積分と面積式の外径は 3 % 以内で一致し（8 mm × 56 巻 → Φ1,506 対 図面 Φ1,510）、
既定条件では 58 巻・Φ1,548 になります。以前の «渡り板がコイルの肉厚中心に刺さる» 見え方は、
渡り板の終点を外径の 35 % という比率で置いていたためで、現在は接線の幾何で決めています。

### コイル押え

押えアームは **サイドトリマー架構の上部梁** から下流へ出したブラケットを支点（トリマー中心から
700 mm・パスライン上 1,700 mm）に揺動し、先端の **金属コロ（Φ200 × 面長 600）** がコイル外周に
接します。下巻きなので狙いは巻き終わり側の **上寄り**（コイル中心から見て真上を 90° として
105〜125°）で、コイルが太るほどアームが起き上がります。コロが当たる極角に巻きかけの層が
あれば 1 枚ぶん外側に乗るので、1 周ごとの段をコロが拾います。駆動は梁上の受けから吊る
シリンダで、巻取をしないパスでは最大コイル径に相当する位置まで退避します。

## 2. 圧延モデル

`Rolling` オブジェクト（純関数の集合）に集約しています。状態を持たないため単体で検証できます。

| 量 | 式 |
|---|---|
| 接触弧長 | `Ld = √(R·Δh − Δh²/4)` |
| 変形抵抗 | `σ = (1/α)·asinh( sinh(α·C)·(Z/Z_ref)^(1/n) )`（Sellars–Tegart の双曲線正弦則）。`Z = ε̇·exp(Q/RT)` は Zener–Hollomon パラメータ。低 Z ではべき乗則、高 Z では指数則へ**式そのものが移る**。n = 1/m、Q と α は «その材質の熱間実験式 C/b/m を最もよく再現する組» として数値的に当てはめる（層温度を渡すと層ごとの平均になる）|
| 変形抵抗の室温上限 | `kf / (1 + (kf/KF_MAX)^p)^(1/p)`,  p = 20。単一の (Q, α) で室温まで外挿できる保証は無い（動的回復が止まって変形機構が変わる。実測で室温の 1.7〜6.1 倍）ので、室温の変形抵抗 KF_MAX を上限として押さえる。p は «角の丸さ» で、p = 4 では上限のはるか手前から効いて熱間域を最大 9.4 % 削っていた。p = 20 なら熱間域の削りは 0.38 %、室温はちょうど KF_MAX に載る |
| 摩擦係数 | `μ = MU·exp(−k_T(T−450))·(V_ref/v)^k_v`（0.14〜0.42 で頭打ち）。温度が上がるほど・速度が上がるほど下がる |
| 中立点・前進率 | `φn = (φ/2)(1 − φ/(2μ))`、`f = R'·φn²/hOut`。出側の材料はロール周速より f だけ速く出る（質量流に反映）|
| ロール表面温度 | 板から受け取った熱でロール胴が温まり、クーラントで待機温度へ戻る。予測と運転が同じ収支を見る |
| 平均ひずみ速度 | `ε̇ = (v/Ld)·ln(hIn/hOut)` |
| 摩擦丘係数 | `Qp = (exp(x)−1)/x`,  `x = μ·Ld/hm` （スラブ法。x→0 で 1 に収束、μ=0.25） |
| 平均面圧 | `pm = 1.155·kf·Qp` （1.155 は平面ひずみ係数） |
| 実接触弧長（ロール扁平） | `Ld = √(R'·Δh − Δh²/4)`、`R' = R(1 + C·P'/Δh)`、`C = 16(1−ν²)/(πE)`（Hitchcock）。荷重 → 扁平 → 接触弧 → 荷重 の陰的関係を緩和つき不動点反復で解く |
| 圧延荷重 | `P = pm·w·Ld·φ`。φ は接触弧の «埋まっている割合» で、噛み込みと尻抜けの Ld/v の間だけ 0→1 に立ち上がる |
| 実ロールギャップ | `h = S + P/M`（S: 圧下位置、M: ミル定数 550 t/mm）。荷重でスタンドが伸びたぶん開く |
| 塑性係数 | `Q = −dF/dh_out` [t/mm]。«板を 1 mm 薄くすると荷重が何 t 増えるか»。解析式が無い（変形抵抗・摩擦丘・ロールの扁平がすべて h_out に依る）ので荷重モデルそのものを数値微分して取る。AGC のフィードフォワードと幅方向のたわみ（クラウン）が同じ 1 か所を見る |
| 板厚制御（AGC） | ゲージメータ（荷重 FB）: `S = h_ref − P/M_est`（制御が思っているミル定数 `M_est` には数 % の同定誤差がある）。モニタ（X 線厚み計 FB、出側 12 m の輸送遅れ）が残留偏差を詰める。フィードフォワードは入側の «これから来る» 板厚を先読みして `ΔS = −δ·Q²/(M(M+Q))` だけ動かす（全量 `δ·Q/M` のうち荷重 FB が受け持たない残り）|
| 長手方向の板厚 | 材料座標 240 分割。各パスは «出たときの実ギャップ» を書き戻し、次のパスがそれを入側厚として読む |
| 端部欠陥（舌） | `D_t = r²·(材質係数)·(1 + 0.8·冷え)·(3·h + 0.3·w)/2`。r は **その端を最後に平らにしてからの圧下**。幅中央がいちばん伸びる（`1 − nz²`）。どのパスでも付き直す |
| 端部欠陥（ワニ口） | 同じ式だが、**Δ = hMean/Ld > 1 のパスでしか育たない**（表層集中変形）。表裏がいちばん開く（`ny²`）。薄板では出ない |
| 幅方向の板厚（クラウン） | 影響係数法。`(I + Q_w·G)·x = G·p̄ + H_b·F_b + crown`。G は «WR 自由端梁 ＋ BUR 単純支持梁 ＋ 線接触» の連立から作る |
| 平坦度（残留応力） | `λ = ln(h_in/h_out)` の幅方向のばらつき。`σ = −E(λ−λ̄)`、`I = (λ−λ̄)×10⁵`。座屈は `σ_cr = kπ²E/(12(1−ν²))(h/b)²` |
| 形状制御 | 目標クラウン `C* = (C_in/h_in)·h_out`（比例クラウン）。`F_b ← F_b + (C* − C)/g`、g はベンディングのクラウン利得 |
| 熱クラウン／摩耗クラウン | ロール半径の 中央 − 端。中凸はギャップを閉じるので板厚への寄与は `−2(研削 + 熱 − 摩耗)` |
| 幅方向の温度 | `ΔT_edge = h_e(T−T∞)t/(ρc_p√(a·t))`、端からの距離に `exp(−d/√(a·t))` で減衰 |
| 幅広がり | `ln(w₁/w₀) = C·exp(−k·w₀/L_d)·ln(h₀/h₁)`（Helmi–Alexander 型） |
| パスライン調整 | `κ_pl = −3δ/L²`（δ: ロール組の上げ量、L: バイト出口から最初のテーブルローラまで）。バイト内の曲率に足してからスプリングバックへ渡す |
| スプリングバック | `κ_e = 2σ_y/(E·h)`、`M = M_p(1 − (1/3)(κ_e/κ)²)`、`κ_perm = κ − M/(EI)`。`κ ≤ κ_e` なら全部戻る |
| 蛇行（くさび） | `Δh = 2·[δ(S/2+w/2) − δ(S/2−w/2)]·P + ゼロ点誤差 − 圧下の傾き`（合力が中心から e ずれた単純支持梁のたわみ差）|
| 蛇行（キャンバー） | `κ_c = (ln(h_in/h_OS) − ln(h_in/h_DS))/w`。横行は `dψ = κ_c·dL`、`dz = ψ·dL` |
| 差荷重制御 | `tilt ← tilt + KP·Δh`（レート・可動範囲つき）。くさびを打ち消す向きに圧下を傾ける |
| 据わり（片側接触） | 「接触は押すだけ」の下で位置エネルギー最小 ＝ 点 (u, −b) の上側凸包を重心で評価。傾きは包絡線の勾配 |
| 端部の冷え | 端面からの放熱（1/Δx）＋ 端が薄いぶんの割増（1/(1−taper)）＋ 炉出し時点の落ち込み。長手の熱伝導で内側へ広がる（平均 0 に正規化して «分布» だけを持つ）|
| トルク／動力 | `M = 2·P·λ·Ld`,  `Power = M·ω`（λ=0.45） |
| 加工発熱 | `ΔT = η·1.155·kf·ln(hIn/hOut)/(ρ·cp)`（η=0.95） |
| 巻取張力 | `T = min(M_reel/(OD/2), 14,480 kgf)`。リール駆動トルク `M_reel` は 550 kW / 300 rpm / 8.5:1 から求める |
| 前方張力 | 巻取パスでは `kf` を `T/(w·h)` ぶん低下させる（上限 30 MPa） |
| ロール抜熱 | `ΔT = (T−T_roll)(1 − exp(−2·h_c·t_c/(ρ·cp·h)))`、h_c = 30 kW/m²K。指数形で飽和させ、両表面から浸透深さ δ = 2√(α·t_c) の層に配分する |
| 表面放熱 | 放射（ε=0.18）＋自然対流（8 W/m²K）。板厚に反比例して効く |
| クーラント冷却 | 上面 800 / 下面 250 W/m²K（膜沸騰域）、液温 40 ℃、冷却域 2.4 m を通過する時間だけ効く |
| 板面冷却 | 水冷 700 W/m²K（受け手＝蒸気膜 105 ℃）／ 空冷 120 W/m²K（受け手＝周囲 30 ℃）／ なし 0。`PhysicsEngine.stripFilm()` が 1 か所で決める |
| 抜熱の飽和 | **すべての抜熱項**を `(T − T_sink)(1 − exp(−x))` の形で書き、合計も «いちばん冷たい受け手» で止める（`Rolling.passTempChange`）|
| 板厚方向の温度 | 9 層の 1 次元熱伝導を陰解法（三重対角）で毎ステップ解く |
| 反り | `κ = 0.04·(kf_top − kf_bot)/kf·ln(h_in/h_out)/h_out`、浮き上がり長 `ℓ = √(2·EI·κ/q)`、先端 `κℓ²/4` |
| コイル外径 | `OD = √(ID² + 4·L·h/π)`（内径 Φ610 から成長、最大 Φ1,900） |

可逆圧延で材料温度を決める主因はロール抜熱です。線形式は低速・厚板で発散するため
指数形（飽和する集中定数解）を使っています。

### 板厚方向の温度分布と上面の偏冷

板は上面から下面まで **9 層** に分け、1 次元の熱伝導を陰解法で解きます。ロール抜熱は
両表面の浸透深さ（2√(α·t_c)、厚板で 10 mm 程度）に集中し、そのあと伝導で均されます。
クーラントは水主体のエマルジョンで、上ロールから **板の上面へ流れ落ちる** ぶんが板を直接
冷やし、下面は流れ落ちないので効きが弱い（上面 800 / 下面 250 W/m²K。400 ℃ 級の面では
膜沸騰になるので 1 kW/m²K 未満に留めています）。冷却域はミル前後 2.4 m で、板がそこを
通過する時間だけ効くため、板全体の平均としては 2.4 m ÷ 板長 に薄まります。

**板面クーラント**（門型 2 基 × ラインに平行なヘッダ OS / DS 各 1 本、冷却域 1,200 mm × 2）は
板の上面へ直接噴射するので、ロールから流れ落ちるぶんとは別に上面へ 700 W/m²K で効きます。
ノズルは**板のクォーター部（ライン中心から ±620 mm）を狙って鉛直から 34° 内向き**に傾けてあります
（`Layout.nozzleDir()`。ヘッダの形状と噴射粒子の向きが同じ式）。
門型は**入側・出側とも「サイドガイドの上」（ミル中心から ±3.4 m）**にあり、
位置は `CONFIG.TABLE.GUIDE.HEADER.STATIONS` に書いて `Layout.coolStations` が解き、
冷却域は `Layout.coolZones()` が返します（描画・熱計算・噴射粒子・諸元表が同じ 1 式を見ます）。板がヘッダの下を
通過している長さ ÷ 板長 の割合（`PhysicsEngine.guideCoolFrac`）で薄めるため、短い厚板ほど強く、
長い薄板ほど平均としては弱く効きます。スケジュール予測も同じ冷却域を含み、
**パススケジュール区分の「板面冷却」（水冷 / 空冷 / なし）**で運転・予測とも切り替わります
（既定は水冷。1 パスあたりの抜熱は 水冷 16.3 K ＞ 空冷 14.1 K ＞ なし 13.5 K）。

その結果、厚板パスでは **上面が下面より 10〜20 ℃ 冷え、芯は 50〜100 ℃ 高い** 分布になり、
変形抵抗は層ごとの平均で見るので同じ平均温度でも荷重が上がります。薄板は伝導で瞬時に均され、
分布はほぼ消えます（«特に厚みが大きいとき» に効く、という実機の感覚と一致）。
モデルの単体検証は `tools/thermcheck.mjs`（放熱速度・抜熱のエネルギー収支）で行っています。

### 反り（上反りと自重たわみ）

上下面の変形抵抗差で上下の伸びが違い、板は硬い側（冷えた上面）へ曲がって **上反り** になります。
曲率 κ は圧延中に通過した分の重み付き平均で決まり、先端側（圧延済み）は新しい反り、
尾端側（未圧延）は前パスの反りを持ちます。

反りは自重と釣り合います。曲げ剛性 `EI = E·w·h³/12`、単位長さ重量 `q = ρ·g·h·w` として

- **テーブル上の端部**は `ℓ = √(2·EI·κ/q)` だけ浮き上がり、先端高さは `κℓ²/4`（スキー）
- **ロールから出たばかりの先端**は片持ち梁で、`κx²/2` の上反りから自重で垂れ、
  自由長が `√2·ℓ` に達するとテーブルに着地する。以後は出口側の形を保ったまま、
  先端にスキーが育つ

先端高さは `EI·κ²/(2q) = E·h²κ²/(24ρg)` で、同じ相対温度差なら板厚によらず同程度です。
厚板は温度差が残るので反りが出て（A7075・60 mm 板の中間パスで先端 230〜265 mm、R ≈ 70〜130 m）、
薄板は温度差が消えるので平坦になります。純アルミ（A1050）は温度依存が小さいので
同じ温度差でも反りは小さくなります（8 mm コイルの粗パスで最大 50 mm）。
数値は `tools/curltrace.mjs` でパスごとに読めます。

板長・板厚は**質量流一定**（出側速度 = ロール周速、入側速度 = 出側速度 × hOut/hIn）で積分するため、
体積が原理的に保存されます。最終体積の差 −2.15 % は数値誤差ではなく、**75 mm シャーが切り落とした端材ぶん**です（端材 800 mm のうち板長として減る健全部 687 mm）。

巻取張力は定数ではなく、**リール駆動トルクとコイル径から導いています**。
リール電動機は 550 kW・基底 300 rpm・減速比 8.5:1 なので、軸トルクは
`550 kW ÷ (300 rpm) × 8.5 ≒ 148.8 kN·m`。張力は `トルク ÷ コイル半径` で、
巻き太るほど下がります。

ここで得られる数値が仕様と整合します。最大コイル径 Φ1,900 でも `148.8 kN·m ÷ 0.95 m ≒ 16.0 ton` で、
仕様の巻取テンション最大 **14,480 kg を上回ります**。つまりこのリールは
「使用コイル径の全域で定格張力を出し切れる」ように電動機が選定されており、
モデル上も張力は径によらず 14,480 kgf で頭打ち（トルク律速に入るのは Φ2,096 以上）になります。
仕様値どうしが独立に整合したので、駆動側の数値の読み方が正しいことの裏付けになっています。

### 材料温度の下限は工程と材質で変わる

粗〜中間パスは熱間域を保つ必要がありますが、**薄板をコイルに仕上げる最終パス以降は
巻取温度まで下がるのが正常**です。下限は材質表から `熱間域下限 − 30 ℃`（圧延中）と
`巻取温度 − 30 ℃`（コイル仕上げ・巻取）を工程で切り替えています。
巻取中は温度低下そのものが工程なので、警告判定の対象から外しています。

### パススケジュールの自動生成

パス数と圧下量は板厚・板幅・材質から `Rolling.buildSchedule()` が生成します。目標板厚は
4〜150 mm で自由に設定でき、10 mm 以下はコイル、10 mm 超は板材として扱います。
1パスあたりの圧下量は **噛み込み角（24°）・圧下率（40 %）・圧延荷重（常用最大の 88 %）** の
3つで律速し、速度は質量流に合わせて上げたうえで **主機動力 3,800 kW の 84 %** で頭打ちにします。
温度は選んだ速度に依存する（低速ほどロールに熱を奪われる）ため、速度→温度→速度 を
反復して収束させています。可逆圧延なので最終材が出側に残るようパス数は奇数にそろえます。

パスは次の3つで律速します。

1. **噛み込み角 24°** — 前段の厚板パスはこれで圧下量が決まる
2. **テーブル長** — 中間パスは終わる側のテーブルに板が載りきる必要がある
3. **主駆動系の包絡線** — 後段の低温パスは所要トルクで速度が決まる（定トルク／定出力）

さらに「各パスを所定時間（150 秒）内に通し切れるか」も条件に入れています。長いパスほど
速く通す必要があり、そこで定格動力を超えるなら圧下量を落とします。温度は速度に依存するので
速度→温度→速度を反復して収束させます。

荷重の上限はパスの «終わり» の温度で見ます。主機は動力律速で低温パスほど遅くなり、
遅いほど通過中に冷えて硬くなるので、入側温度と参照速度で組むと薄板の後段（特に巻取パス）で
実荷重が上限を超えます。さらに運転時は表層が冷えて変形抵抗が層平均で上がるため、
集中定数の予測より実荷重が 2〜3 割高くなります。スケジュールは常用最大の 70 % で組み、
実荷重が常用最大 3,920 t を超えないようにしています。

**検証結果**（A3003・既定、呼び厚 406 − 面削 2×12 = 382 mm、幅 1,500 mm、コイル 8 mm、板面クーラント ON）:

| 指標 | 値 |
|---|---|
| パス数 | 9（可逆・最終パスで巻取） |
| 最大圧延荷重 | 1,685 t（常用最大 3,920 t の 43 %） |
| 最大主機動力 | 3,391 kW（定格 3,800 kW の 89 %） |
| 巻取温度（平均） | 312 ℃（板面クーラント OFF では 342 ℃） |
| コイル | 外径 Φ1,563 ／ 6,528 kg ／ 59 巻 ／ 仕上げ幅 1,470 mm |
| 端部切断 | 2 カット × 400 mm（欠陥長 ≈ 675 mm + 余裕 120 mm を切り上げ）。端材は切断時の形のままコンベアでパレットへ |
| 体積収支 | −0.42 %（＝切り落とした健全部のぶん） |
| サイクル時間 | 474 秒（7.9 分。装入は A-9 から約 29 m の搬送を含む） |

重圧下パスは低速、薄板パスは高速という実機どおりの姿になります。
主機は定格を超えるトルクを出せないため、運転時にも動力リミッタで自動的に減速します。
A5052 では 5000 系の温度依存性のため巻取パス（14.7 → 8.1 mm、入側テーブル長で決まる）が
動力律速で遅くなり、巻取温度は 277 ℃ まで下がって最大荷重は常用最大の 88 %、主機動力は
定格の 100 % に達します（完走はするが余裕が無い、と事前に注記されます）。

### 成立しない条件は事前に警告し、運転すれば過負荷停止する

スケジュールには各パスの予測荷重（終端温度・動力律速速度・巻取張力で見た値に、厚板ほど残る
表層硬化ぶん 1.0〜1.25 を掛けたもの）と終端温度を持たせ、`Rolling.scheduleFeasibility()` が
**予測荷重が非常最大の 1.1 倍（予測の不確かさ ±10 % を見込む）を超える** か
**最終パスの終端温度が材質の下限を 30 ℃ 以上割る** 場合に «このラインでは成立しない» と判定して、
素材パネルに理由を出します。常用最大の 90 % を超える、または下限をわずかに割る場合は
«余裕なし» の注記になります。スケジュール表の荷重列は運転前は予測値（灰色）、運転中は実測の最大値です。
予測は保守側に 10〜20 % 程度で、A5052・8 mm では予測 4,231 t に対して実測 3,460 t でした。

それでも運転した場合、実機と同じく **非常最大圧延荷重 4,200 t を超えた時点で主機を止めて運転を
打ち切ります**（過負荷停止）。例えば A7075 を 8 mm コイルに仕上げようとすると、熱間域が
360〜450 ℃ と狭く薄板パスで温度が保てないため、動力律速 → 減速 → 冷却 → 硬化の悪循環に入り、
第 6 パスで過負荷停止します。これは «この材質・板厚はこのラインでは作れない» という
物理的な結論で、成立させるには炉出し温度・板厚・材質の見直しが要ります。

### 意図的に採用しなかった表現

アルミニウムの熱間圧延温度域（400–540 ℃）では材料は**可視発光しません**（赤熱は 600 ℃ 以上）。
そのため赤熱表現は行わず、温度は色味と表面粗さの微差、および水蒸気・クーラント演出で示しています。
クーラントも材料への直接噴射ではなく、実機同様ワークロール面への潤滑エマルジョン噴射としています。

### 水蒸気とクーラントの描画

粒子は 2 系統あり、どちらも 1 ドローコールの点スプライトです。

クーラントは **水を主成分とするエマルジョン（油分 6 wt% 程度）** です。したがって
ミル上に立ち上がる白煙の主成分は **水蒸気** であり、油煙ではありません。発生量は
«水がどれだけ蒸発できるか» で決まるので、材料温度に比例させています
（120 ℃ で発生し始め、480 ℃ で飽和）。仕上げの低温パスでは薄くなります。

| | 水蒸気 | クーラント液滴 |
|---|---|---|
| 発生源 | ロールバイト出側（エマルジョンの水が熱で蒸発） | ワークロール面（エマルジョン噴射） |
| 粒数（上限） | 300 | 800 |
| 初期径 → 末端径 | 620〜1,140 mm → 2.6 倍 | 70〜140 mm → 1.3 倍 |
| 鉛直加速度 | 浮力 +2,000 mm/s²、抗力 0.95 /s（終端上昇速度 2.1 m/s） | 重力 −9,810 mm/s² |
| 寿命 | 2.4〜4.2 s | 0.45〜0.80 s |
| 放出レート | (30 + 0.50 × ライン速度) × 温度係数 [1/s] | 620 /s |

点スプライトが「四角い塊」に見えるのは輪郭が矩形で切り落とされるためなので、
**中心から滑らかに消えるアルファ**を持つテクスチャを起動時に Canvas で生成して共有し
（画像ファイルは持ちません）、粒ごとに **向き・大きさ・濃さ・色** を変えています。
油煙用のテクスチャは単純な放射グラデーションではなく、小さな塊を重ねて輪郭を崩した
不定形のパフです。粒は寿命に沿って **膨らみながら薄れ**（体積が保たれれば濃度は下がる）、
立ち上がりも滑らかにして唐突な出現を避けています。

速度は `v' = 浮力 − 抗力·v` の**解析解**で積分しているため、フレームレートが変わっても
軌跡が変わりません。放出数も端数を次フレームへ繰り越す方式にして、dt 非依存にしています。
粒径が大きいぶん塗り面積が効くので、描画品質「軽量」では放出量を 40 % に落とします。

**粒は「小さく多く」ではなく「大きく少なく」**にしています。小さい粒を多数撒くと遠景で
«点の集合» に見えてしまい、塗り面積も増えるためです。濃度は目視ではなく、水蒸気
ON/OFF のキャンバス画素差を測って決めました。

## 2-2. 頭と尾で荷重が上がる理由（実機の話）

実機で «噛み込んだ瞬間» と «頭・尾» の荷重が高くなるのは、**単一の原因ではなく 6 つの要因の重ね合わせ**です。
本アプリが再現しているものと、していないものを分けて書きます。

| # | 要因 | 中身 | 本アプリ |
|---|---|---|---|
| 1 | **端部の温度低下** | 端面（幅×板厚）からも放熱するので単位体積あたりの放熱面積が大きい。炉内でも端は扉・炉壁に近く、抽出から圧延開始までの搬送でも端から冷える。さらに端は舌・ワニ口で薄く広がっており、薄い＝冷えやすい。可逆圧延では往復のたびに端がテーブル上で待つ。変形抵抗は温度に指数で効くので、**30 K の低下で 15〜20 % 硬くなる** | ○ 実装 |
| 2 | **張力が掛からない** | 前方・後方張力は圧下力を実質的に下げる。頭は巻取機に噛むまで、尾は尻抜けで張力が消えるので、**頭尾だけ «無張力圧延»** になる。実務でいちばん効く要因 | △ 巻取パスのみ |
| 3 | **前パスが残した板厚偏差** | 前のパスの頭尾も同じ理由で公称から外れる（AGC が収束していない・無張力で厚め）。次のパスではその厚い部分が入るので圧下量が増える。**パスを重ねるほど累積する** | ○ 実装（材料座標のプロファイル） |
| 4 | **板厚制御の過渡** | ゲージメータ AGC はミル定数の推定誤差ぶん残留偏差を持ち、X 線厚み計は出側に離れているので**頭が計器に届くまで補正が入らない**（輸送遅れ）。圧下自身にも応答遅れがある。つまり頭の数 m は実質「開ループ」 | ○ 実装 |
| 5 | **噛み込みの衝撃** | 圧下はミルの伸び `F/M` を見込んで締めてあるので、荷重が立つまでの数十 ms は**狭い無負荷ギャップがそのまま材料に当たる**。加えてスタンドの質量とばね（固有振動数 10〜30 Hz）が階段状の荷重で励振され、チョック・圧下ねじの «がた» が荷重で詰まるまで実ギャップは設定より狭い。頭はクロップで直角に切られており、噛み込み条件も定常より厳しい | ○ 実装（スタンドの伸びは 2 次系 15 Hz・ζ 0.35。ロードセル値＝伸び × ミル定数の行き過ぎが衝撃として出る。がたは未実装） |
| 6 | **潤滑膜が未形成** | ロールバイトの潤滑膜は材料が入って初めてできる。頭は乾いた状態で噛むので**摩擦係数が高く、摩擦丘が大きくなる**（面圧が上がる） | ○ 実装（`PROCESS.MU_HEAD`: 頭で μ +25 %、1 m で膜が育つ。係数は文献的な目安） |

尾端にはさらに «尻跳ね»（tail flick）で板が暴れ、瞬間的な片当たり荷重が出るという固有の現象もあります。

### 2-2-2. 頭尾の荷重差の分解と修正（VER.1.15.0）

`tools/headtail.mjs` は、頭帯（0〜1.5 m）・内側・尻帯のそれぞれで **入側板厚・局所温度・速度・実ギャップ** を平均し、
荷重モデルを数値微分して «荷重差のうち何がどれだけか» を出します。修正前の既定ロット:

| パス | 出側厚 | 頭 荷重比 | 尻 荷重比 | 尻の温度差 | 尻の温度寄与 |
|---|---|---|---|---|---|
| 5 | 132 mm | 0.975 | 1.115 | −19.5 K | +12.3 % |
| 8 | 31.6 mm | 1.048 | 1.347 | −43.2 K | +35.6 % |
| 11 | 12.8 mm | 1.163 | 1.232 | −51.1 K | +45.5 % |

尻が高い理由のほぼ全部が **温度** で、その温度差は物理ではなく **計算の取り違え** でした。

1. **ロール抜熱の帰属** —— 加工発熱は «通った材料点» へ積んでいたのに、ロール抜熱は板全体の層平均からだけ引いていた。
   長手方向の分布は «平均 0» で持つ約束なので、まだ通っていない尻が «頭が受けた抜熱» ぶんまで冷たく読まれる。
   → 発熱と抜熱を同じ点へ同じ扱いで積む（`SlabState.writeHeat(heat − chill)`）。
2. **噴射冷却の帰属** —— ロールクーラント（ミル前後 2.4 m）と板面冷却（ヘッダ下）も «噴射域 ÷ 板長» に薄めて平均へ
   入れるだけだったので、尻はバイトに入る時点で **このパスの噴射量を丸ごと**受けた温度になり、頭はゼロ。実機では
   頭も尻も «自分がくぐったぶん» しか冷えない。→ 噴射域の下に居る材料点へ実際の熱流ぶんを引く（`PhysicsEngine._localCool`）。
3. **バイトに入る前の温度** —— 噛んでいるセルへ発熱をその場で積み、同じセルを読んで荷重を解いていたため、
   局所温度が 1 セルごとに 13 K の鋸歯になり平均で 6 K 高い側へ寄っていた。→ このパスの正味の熱を引いた
   «入る前» の温度で解く（`SlabState.dTEntry`）。

板厚側では、**圧下の事前設定が予測荷重（実測の約 1.5 倍）で締めすぎ**、噛み込み直後のギャップが 1〜2 mm 狭く
（第 9 パスで 20.2 mm、狙い 22.2 mm）、頭が薄く出ていました。実機のセットアップモデルは前パスの実測で予測を補正する
（荷重学習）ので、同じことをします（`AGC.ADAPT`）。さらに、ご指摘の **«2 次応答の遅れ»** をスタンドの伸びの
2 次系（`MILL.STAND`）として入れ、**頭尾 AGC ロック**（`AGC.END_HOLD`）で過渡を板厚偏差と誤読しないようにし、
計器・記録・AGC が読む荷重を **ロードセル値（伸び × ミル定数）** にしました。これで «厚い頭» が実際に出ます。

修正後（`loadtrace.mjs` の頭／尻 ＝ その端の 1.5 m ÷ そのすぐ内側）:

| パス | 4 | 5 | 6 | 7 | 8 | 9 | 10 | 11 |
|---|---|---|---|---|---|---|---|---|
| 頭 | 1.007 | 1.040 | 1.065 | 1.049 | 1.053 | 1.033 | 1.049 | 1.025 |
| 尻 | 1.033 | 1.017 | 1.044 | 1.030 | 1.035 | 1.068 | 1.055 | 1.087 |
| 衝撃 | 1.046 | 1.076 | 1.094 | 1.078 | 1.117 | 1.128 | 1.151 | 1.110 |

第 4〜8 パスは頭・尻が同等、第 9〜11 パス（板長 40〜77 m、パス時間 40〜50 s）は尻が +2〜6 % 高く残ります。
残りは **パス中に板全体が冷える速さ（放射 ＋ 対流 ＋ テーブル接触で 0.3〜0.5 K/s）× パス時間 ＝ 15〜23 K** で、
実機でも薄い長尺パスで «尾上がり» として観測される物理量です。ご指摘の仮説については:
«噛み込み直後の頭が厚く出る» と «それが次パスの尻へ持ち越される» は再現されました（尻の入側厚 +0.2〜0.3 mm →
荷重 +2〜5 %）。ただし **累積はしません** —— ロック区間の外では荷重 FB が 97 % を打ち消すので、2 パス先の頭には
3 % しか戻りません。頭と尻を同等にしているのは累積ではなく、①〜③ の是正と、頭の側の潤滑膜（#6）です。
なお **分からないこと**: 実機の頭が尻と同等になっている残りの理由（尻抜け減速の有無、圧下の «がた»、頭の温度）は
本アプリの情報だけでは決められません。`PROCESS.MU_HEAD` の係数はその意味で «目安» で、0 にすれば効きを消せます。

## 2-3. 精度を上げるために «まだ入れていない» 理論

本アプリの圧延モデルは «スラブ法 ＋ 摩擦丘 ＋ 集中定数の熱» という古典的な組み立てです。
実機データに寄せるなら、効果の大きい順に次が残っています。

**A. 圧延理論**

| 項目 | 中身と効き方 |
|---|---|
| **ロールの弾性扁平（Hitchcock）** | 荷重でロールが平たくつぶれ、接触弧長が `Ld' = Ld·√(1 + C·P/(w·Δh))` のように伸びる。**薄板ほど支配的で、薄物では Ld が 1.3〜2 倍**になり荷重が跳ね上がる。今は剛体ロール前提なので、薄板パスの荷重を過小に見ている。**未実装の中でいちばん効く** |
| **Orowan / Sims の解** | 中立点と前後進率を陽に解く。圧下率が大きい領域と、張力が効く領域で精度が上がる |
| **前進率（forward slip）** | 出側速度はロール周速より 2〜8 % 速い。マスフローとトルク配分、そして «速度計から板厚を出す» 制御の精度に効く |
| **摩擦の状態依存** | μ は温度・速度・ロール粗さ・エマルジョン濃度で変わる。さらに高温アルミは «固着域» を持つので、クーロン摩擦だけでは面圧を過大評価する（せん断摩擦係数 m との併用） |

**B. 材料モデル**

| 項目 | 中身と効き方 |
|---|---|
| **Zener–Hollomon ＋ sinh 型構成式** | `Z = ε̇·exp(Q/RT)`、`kf = (1/α)·sinh⁻¹((Z/A)^(1/n))`（Sellars–Tegart）。いまの `C·exp(−bΔT)·ε̇^m` より広い温度・ひずみ速度域で合い、活性化エネルギー Q を材質ごとに持てる |
| **ひずみ依存（加工硬化と動的回復）** | いまの kf はひずみに依存しない。実際は加工硬化と動的回復・動的再結晶の釣り合いで決まる |
| **パス間軟化（静的再結晶）** | パス間の «待ち時間» で軟化が進む（Avrami 型）。可逆圧延はパス間が長いので効く。累積ひずみの持ち越し量が変わる |
| **析出・固溶状態** | 5000 系の Mg 固溶、3000 系の Mn 分散相など。長時間の高温保持で変わる |

**C. 熱**

| 項目 | 中身と効き方 |
|---|---|
| **ロール温度の履歴** | いまはロール表面 80 ℃ 一定。実際はロール自身が加熱され、周方向にも温度分布を持ち、パスを重ねるほど上がる（＝抜熱が弱くなる）。サーマルクラウンにも直結する |
| **界面熱伝達係数の圧力依存** | `h_c` は接触圧力・酸化膜・潤滑膜で 2〜10 倍変わる。いまは一定 30 kW/m²K |
| **幅方向の温度分布** | いまは幅一様。実際はエッジが冷えて «エッジドロップ» と形状不良の原因になる |
| **加工発熱の分布** | せん断帯に集中し、板厚方向に一様ではない |

**D. 機械・形状**

| 項目 | 中身と効き方 |
|---|---|
| **ロールたわみと板クラウン** | 荷重で WR がたわみ、板厚が幅方向に変わる。影響係数法か有限要素で «荷重分布 → たわみ → 板厚分布 → 荷重分布» を収束させる。いまはロールベンディングもクラウンも描画だけで力学に入っていない |
| **サーマルクラウン・摩耗クラウン** | ロール径が幅方向・時間方向に変わる。長時間運転の形状変化の主因 |

## 2-4. 板の «形状・反り・歪み» —— いま入っているもの / 足りないもの

形状の精度は「①**断面（幅方向）の板厚分布**をどう決めるか」「②**長手の曲がり（反り）**を
どう解くか」「③**残留応力と平坦度**をどう結びつけるか」の 3 つで決まります。
現状は ② の一部だけが力学として入っていて、① と ③ は入っていません。

### いま «力学として» 入っているもの

| 項目 | 実装 |
|---|---|
| 上下非対称による反り（曲率） | `SlabState.curl` —— 上下ロール周速差・上下温度差・摩擦差から曲率 κ を積む |
| 自重と曲げ剛性の釣り合い | `Rolling.curlSpan(κ, h, w, alloy)` —— 曲げ剛性 `EI = E·w·h³/12`、自重の分布荷重 `q = ρ·g·h·w` を出し、**浮き上がり長 `ℓ = √(2·(EI/q)·κ)`**、先端高さ `κℓ²/4`、着地距離 `√2·ℓ` を決める |
| ロールから出た片持ちのたわみ | `Rolling.cantileverLift` —— 曲率による持ち上がりから**自重による垂れ `−x²(6ℓ²−4ℓx+x²)/(24·EI/q)`** を引く |
| テーブル上のスキー（浮き上がり） | `Rolling.skiLift` —— 端が浮き、根元でテーブルに接する形 |
| 端部欠陥（舌・ワニ口） | `SlabState.overhangParts` —— 舌は幅方向の不均一な広がり、ワニ口は表層集中変形（Δ = hMean/Ld > 1） |
| 長手の板厚プロファイル | `hProf`（材料座標 240 分割）—— 各パスが «出たときの実ギャップ» を書き戻す |
| 断面の鋳肌ラウンド | `Sect` —— 鋳造ままのコーナー半径が面削で頂部を削られ、圧延で自己相似に縮む |

**したがって「自重・たわみは考慮されているか」への答えは «曲げの釣り合いとしては入っている» です。**
反った端がどこまで浮くか（ℓ）も、先端がどこで着地するか（√2·ℓ）も、片持ちがどれだけ垂れるかも、
すべて `EI/q` ＝ 曲げ剛性 ÷ 自重 から出しています。板厚が薄いほど `EI ∝ h³` が効いて浮き上がり長が
短くなる、という «実機の見え方» はここから自然に出ます。

> **VER.1.9.0 で下表の 1〜7 を、VER.1.11.0 で 6（スプリングバック）と 8（蛇行）を実装し、
> これで下表はすべて実装済みになりました。** 実装後の実測は本文末を参照してください。

### 形状に効く順（すべて実装済み）

| # | 項目 | いま何が起きているか / 入れると何が変わるか |
|---|---|---|
| 1 | **ロールたわみ ＋ 板クラウン（影響係数法）** | 幅方向の板厚分布が無い。荷重で WR がたわみ、板の中央が厚くなる（クラウン）。«荷重分布 → ロールたわみ → 板厚分布 → 荷重分布» を収束させないと、**クラウン率・エッジドロップ・平坦度が一切出せない**。形状精度の本丸 |
| 2 | **平坦度（残留応力）判定** | クラウン率の «変化» が伸び差になり、伸び差が残留応力になる。中伸び（センターバックル）／耳伸び（エッジウェーブ）はここから出る。判定式は `Δε = Δ(C/h)`、座屈するかは板厚・幅・応力から。**いまは反りしか無く «平坦度» の概念が無い** |
| 3 | **剛体としての釣り合い（片当たり・傾き）** | ご指摘の点です。両端が上へ反ると板は中央付近だけでテーブルに乗り、**支持が 1 点に近づくので前後どちらかへ傾きます**。いまは «両端のリフトを `Math.max` で合成する» だけで、**片側接触（unilateral contact）を解いていません**。入れるべきは «接触点は圧縮しか伝えない» という条件のもとで重心と支持点の釣り合いを解くこと（LCP）。これを入れると、傾く向きが自重（重心位置）と反りの左右差から決まり、テーブルローラとの**離散接触**（ローラ 1 本ごとの当たり）まで表せる |
| 4 | **幅方向の温度分布** | いまは幅一様。実際はエッジが冷えて変形抵抗が上がり、エッジドロップと形状不良の直接原因になる |
| 5 | **サーマルクラウン・摩耗クラウン** | ロール径が幅方向・時間方向に変わる。長時間運転の形状変化の主因 |
| 6 | **弾塑性の履歴（バウシンガ・スプリングバック）** | 反りを «曲率をそのまま形にする» のではなく、除荷でどれだけ戻るかを解く。厚板では戻り量が無視できない |
| 7 | **幅広がり（spread）** | いまは幅一定。スラブ厚 500 mm 級の第 1〜3 パスでは数 % 広がり、これが端部の «舌» の実体でもある |
| 8 | **クロス／ワンダリング（蛇行）** | 板が幅方向にずれて走る現象。サイドガイドの当たり、片伸び、張力の左右差から出る |

**3 番（片当たり・傾き）は «自重を入れる» という話ではなく «支持条件を解く» という話**である点が
勘所です。自重（q）はすでに入っていて、足りなかったのは «接触は押すだけで引けない» という
不等式条件と、その下での剛体の釣り合いでした。

### 実装後（VER.1.9.0）—— 幅方向の形状

ロール系のたわみは **影響係数法** で解いています。WR は自由端梁、BUR は軸受間（3,600 mm）の
単純支持梁、両者は **ヘルツ線接触でつぶれる**（2.85 t/mm per mm）という連立を

```
  y_WR − y_BUR = q/k          接触のつぶれ
  y_WR = A·(p − q) + y_b      WR（自由端梁。p: 板荷重、q: BUR からの反力、y_b: ベンディング）
  y_BUR = B·q                 BUR（軸受間の単純支持梁）
⇒ (A + B + I/k)·q + c·1 + t·z = A·p + y_b     （c, t は剛体運動）
  ∫q = ∫p + 2F_b,  ∫q·z = ∫p·z                 （WR の力とモーメントの釣り合い）
```

として (n+2)×(n+2) で解き、ここから «板荷重 → ギャップ» の影響係数 G と
«ベンディング → ギャップ» の Hb を作ります。板の側は塑性係数
`Q_w = −dP′/dh_out`（`Rolling.solve` の数値微分）で閉じるので、全体は

```
  (I + Q_w·G)·x = G·p̄ + H_b·F_b + crown
```

という線形方程式 1 本になります（x は零平均の板厚偏差）。

**平坦度は «クラウン率 C/h の変化» で決まります。** 入側と出側で C/h が同じなら、
どれだけクラウンが付いていても伸びは幅方向に一様＝平坦です（比例クラウンの原則）。
崩れたぶんが伸び差 λ になり、板は 1 枚なので長さが揃わねばならず、差が
残留応力 `σ = −E(λ − λ̄)` と I-unit `(λ − λ̄)×10⁵` になります。

|---|---|---|---|---|---|---|---|---|
| 1 | 455.4 | 1,433 | −24.6 | −0.005 | −6.4 |  5.4 | 平坦 |   0 |
| 4 | 212.9 | 2,036 |  −8.7 | −0.004 | −4.5 |  2.1 | 平坦 |  12 |
| 6 |  75.3 | 2,756 |  −0.6 | −0.001 | −5.2 |  9.9 | 中伸び |  49 |

### 反りの «残り方» —— スプリングバック（VER.1.11.0）

バイトの中で付いた曲率がそのまま形になるわけではありません。出口で荷重が抜けると
弾性のぶんだけ戻り、残るのは塑性変形した分だけです。断面を弾完全塑性の長方形と見ると
モーメント–曲率が厳密に書けます。

```
  κ_e = 2σ_y/(E·h)                  表面が降伏し始める曲率
  M   = M_p·(1 − (1/3)(κ_e/κ)²)     κ ≥ κ_e（M_p = σ_y·b·h²/4）
  κ_perm = κ − M/(E·I)              除荷は弾性なので、この曲率だけ戻る
```

`κ ≤ κ_e` なら断面はまだ弾性なので**すべて戻って形は残りません**。実測（既定ロット）:

| パス | 出厚 mm | 上下 ΔT | バイト内 半径 m | 残る反り 半径 m | 弾性限界 半径 m | κ/κ_e |
|---|---|---|---|---|---|---|
| 1 | 455.4 | 12.1 | — | **平ら（弾性で戻る）** | 276.8 | 0.8 |
| 2 | 374.6 | 21.8 | 124.9 | 1,875.6 | 208.5 | 1.67 |
| 4 | 213.0 | 30.6 | 30.1 | **78.2** | 99.6 | 3.31 |
| 5 | 132.2 | 26.9 | 17.9 | **32.5** | 54.9 | 3.07 |
| 6 | 75.3 | 11.0 | 23.4 | 75.9 | 24.6 | 1.05 |
| 7〜11 | 47.9〜12.0 | 3.1〜0.0 | — | **平ら（弾性で戻る）** | 12.1〜1.3 | < 1 |

**残る反りを作っているのは中盤の厚いパスだけ**で、薄いパスは弾性で戻ります ——
実機で「厚板パスで頭が跳ね上がり、薄板パスは平らに走る」のと同じ向きです。

### 蛇行 —— キャンバーと差荷重制御（VER.1.11.0）

```
  ロールギャップの左右差（くさび）→ 両耳の伸びの差 → 平面内の曲がり → 横行
                    ↑                                              │
                    └────── 荷重の合力が中心から外れる ←───────────┘
```

くさびは**ミルのゼロ点誤差**（0.02 mm）と、**板がミル中心からずれることで
荷重の合力が外れてロール系が傾くぶん**から出ます。後者があるため
**正の帰還**になり、放っておくと発散します —— これが実機で蛇行が
一度始まると止まらない理由です。断ち切るのが**差荷重制御（自動レベリング）**で、
OS / DS の荷重差が出ないように圧下を傾けます。実測:

|---|---|---|
| 平均キャンバー | 6.09×10⁻⁷ 1/mm | **3.42×10⁻⁹ 1/mm**（178 分の 1）|
| サイドガイド接触 | 288.3 s | **1.9 s** |
| 最大の横ずれ | — | 10.0 mm（ガイドの余裕 10 mm）|

### 板反りの «対策» とその効果（VER.1.12.0）

実機で使う 2 つの手を運転から操作でき、効果が数字で出ます。

**① パスライン調整（WR）** —— ロールの組をテーブルに対して上下させる。
バイトを出た板は最初のテーブルローラ（750 mm）まで δ だけ戻らねばならないので、
根元に `κ_pl = −3δ/L²` の曲げが入る。スプリングバックと組で効くので、
**小さいうちは除荷で戻って反りは変わらず、ある程度動かすと効き始める**。

| パスライン | \|κ\| 1/mm | 上反り κ | 下反り κ | 端の浮き mm |
|---|---|---|---|---|
| −20 mm | 1.38×10⁻⁴ | 1.38×10⁻⁴ | 0 | 24,684 |
| −10 mm | 8.53×10⁻⁵ | 8.53×10⁻⁵ | 0 | 17,190 |
| 0 mm（基準）| 3.26×10⁻⁵ | 3.26×10⁻⁵ | 0 | 1,472 |
| **+5 mm** | **2.07×10⁻⁵** | 8.77×10⁻⁶ | −2.07×10⁻⁵ | **106 ← 最適** |
| +10 mm | 4.74×10⁻⁵ | 0 | −4.74×10⁻⁵ | 0（下反りへ）|
| +30 mm | 1.54×10⁻⁴ | 0 | −1.54×10⁻⁴ | 0（打ち消し過ぎ）|

**② 板面冷却の入側／出側 ON/OFF** —— クーラントは**板の上面にだけ**掛かるので、
片側を切ると上下の温度差が変わり、変形抵抗の差（＝反りの駆動力）が変わる。

| 設定 | 端の浮き | 上下 ΔT |
|---|---|---|
| 両方 ON（基準）| 1,425 mm | 30.7 K |
| 入側 OFF | 321 mm | 24.5 K |
| 両方 OFF | 29 mm | 16.5 K |

熱計算・スケジュール予測・噴射の描画・諸元表がすべて同じ 1 式
（`Layout.coolHeaderXs`）を見るので、切った瞬間から予測も描画も追従します。


## 3. 構造

```
CONFIG          全寸法を mm 単位で保持する単一の真実（ALLOYS: 材質表）。3D 空間へは Sim.u() でのみ変換する
Num             時間積分ユーティリティ（approach / rateTo）。dt 非依存を構造的に保証する
Rolling         圧延理論（純関数）: 変形抵抗・荷重・温度・反り・コイル層・端部切断計画・仕上げ振分け
State           SlabState（層温度・反り）/ MillState / SupplyState / FinishState（巻き層・拡縮・払い出し）
Controller      MillController / SupplyController / FinishController（クロップ・巻取・払い出し）
PhysicsEngine   任意 dt を受け取り 1/120 s の固定ステップに分割して積分。板厚方向の熱伝導は陰解法
MAT / G / Parts マテリアル登録・ジオメトリ生成器・部材ライブラリ
CoilGeometry    段付きコイル（完成した層の環 + 巻きかけの扇形 + 段）を固定頂点数で更新する
View            MillStand / Drive / Table / Guide / Finish / Supply / Slab / Spray / Label
World3D         シーン・ライティング・カメラ・描画品質
UIManager       操作系・計器・状態バナー。待機中の素材変更は即時反映
```

描画と物理が同じ量を別々に計算しない、という原則を保っています。板の入口 A、下台の
持ち上げ量、反りの形、端部欠陥長、コイルの層と接点は、いずれも物理側の 1 か所を
描画側が参照します。

### 断面表示（どこを透かすかを選べる）

構造物が視界を塞ぐと «圧延の様子» が見えません。そこで各ビューは自分のメッシュを
**手前側（オペレータ側）／奥側（駆動側）／天面（板の上に架かる部材）** に分けて登録し、World3D は
その登録内容だけを見て透過を切り替えます。設備を追加しても切替ロジックは変わりません。

| モード | 効果 |
|---|---|
| 実体 | すべて不透明 |
| 半断面（既定） | 手前側と天面を透過。奥行きを保ったまま中が見える |
| 透視 | 手前・奥・天面とも透過 |

«天面» は 75 mm シャーのクロスヘッド・上刃ホルダ・プッシャレール、30 mm シャーのクロスヘッドと
シリンダ、板面クーラントの梁で、いずれも真上から板を隠す部材です。固定上刃・下刃（刃物色）、下台、
板、端材は «切れていることが見えるべき部材» なので透過しません。

さらに **どの設備に適用するか**（圧延機 / サイドガイド / 出側設備 / 装入設備）を
個別に選べます。既定は装入設備を除く 3 つ。板に接するローラ類（ワークロール・
サイドガイドローラ・テーブルローラ）は «当たっていることが見えるべき部材» なので
透過対象から外しています。

`PhysicsEngine.update(dt)` は内部で固定ステップに分割するため、**12 fps でも 144 fps でも結果が一致します**
（12 / 30 / 60 / 144 fps いずれも最終板長 193.81 m・9 パスで完全一致）。シミュレーション速度スライダは入力 dt を倍率変更するだけで、
物理結果には影響しません。

繰り返し部材（テーブルローラ約 160 本・架台・ガイドローラ・チョック等）は `InstancedMesh` に集約し、
テーブルは区間分割して視界外をフラスタムカリングで落としています。静的部材は `mergeGeometries` で
1 メッシュに畳んでいます。

環境反射（PMREM）はフラグメント単価が高いため、**磨かれた金属部材にのみ**適用し、画面占有面積の
大きい塗装構造物・床には適用していません。描画品質は「高 / 標準 / 軽量」で切り替えられ、
起動直後にフレームレートを実測して 20 fps を下回る環境では自動的に軽量へ切り替わります。

### 意図しない接触の全数検査（`tools/interfere.mjs`）

「板がどこかに当たっていないか」は目視では追いきれないので、**評価器**を用意しました。

1. 圧延サイクルを回しながら 0.5 秒ごとにサンプリングする
2. その時刻の板の占有ボックス（板厚・板幅・先尾端）を作る
3. シーン中の全メッシュを**三角形単位の AABB** に落とし、板ボックスと重なるものを拾う
4. **当たってよい部材**（ワークロール・テーブルローラ・サイドガイドローラ・トリマー刃・
   スリーロール・シャー刃・マンドレル・押えロール等）を除外し、残りを干渉として報告する

この検査で見つかり、修正した実例：

| 部材 | 症状 | 原因と対策 |
|---|---|---|
| クーラントヘッダ | 382 mm スラブに 49 mm 食い込む | ロール表面からの距離で置いていたため、圧下量が大きいとパスライン内に入っていた。**ロール軸心からの距離**（内側へ 220 mm）で置き直した |
| トリマー刃物軸 | 通し軸が板の上を横切る | OS/DS 別の**片持ち軸**に分離。刃位置に合わせて張り出し量が変わる |
| トリマー上刃 | 厚板パスで板に当たる | 図面の開位置 ±305 mm は薄板時のもの。**板厚 + 刃半径 + 30 mm** まで自動退避させる |

この検査は 75 mm シャーの作り直しでも働きました。エプロンの脚・側レール・払い出しプッシャが
それぞれ «刃の通り道» や «板の通る範囲» に入り込んでいたのを検出し、位置を直しています。

現在の検査結果は **干渉 0 件**です。

### 静的構造の全数検査（`tools/structure.mjs`）

«ピットの上に架台が立っている» «基礎が床下に潜っている» «梁が宙に浮いている» は目視で
見落としやすいので、可動部を除くすべてのメッシュについて機械的に判定します。

1. **接地**: 底面が床（y = 0）かピット床（y = −3,600・ピット内）に着いている部材を接地とし、
   接地部材に 10 mm 以内で接している部材を連鎖的に «支持されている» とする。床版を貫く部材
   （ピット外で底面が床下）は不成立
2. **開口上の浮き**: 床面高さの底面が圧延機ピット・ピット炉の開口の真上に無いか
3. **食い込み**: 別メッシュどうしの三角形 AABB が 20 mm を超えて重なっていないか
4. **体積の食い込み（レイキャスト）**: 3 は軸に平行な面どうし（箱と箱）の重なりを拾えない
   （平らな三角形はその軸方向の厚みが 0 で、重なり量が 0 になる）。そこで部材 A の頂点・重心が
   部材 B の中にあるかをレイの交差回数（偶奇）で判定し、中にある点から 6 軸方向の最近面までの
   距離を食い込み深さとする。今回これを加えたところ、以前の 0 件の裏に **32 件**（トリマー基礎と
   3ロール基礎、巻取機の駆動側架台とテーブル架台、ハウジングを貫くタイビーム、細ピッチ区間で
   隣どうしが重なる架台、新設のシャー・板面クーラント架台の柱など）があり、すべて位置・寸法を
   直して 0 件にした

現在は接地不成立・開口上・食い込み（三角形 AABB・レイキャストとも）**すべて 0 件**です。装入工程は
`tools/supplytrace.mjs` が、回転するスラブと装入設備（転倒機・クレーン・走行路）の三角形を分離軸判定で
照合し、**食い込み 0 件**です。

| キー | 動作 |
|---|---|
| `Space` | 圧延サイクル開始 / 中止 |
| `P` | 一時停止 / 再開 |
| `R` | リセット |
| `L` | 設備ラベル表示切替 |
| `C` | 断面表示切替（実体 / 半断面 / 透視） |
| `1`–`9`, `0` | 視点切替（全景 / 圧延機 / ロールバイト / 駆動側 / 装入設備 / 巻取設備 / 75mmシャー / 30mmシャー・パイラー / 板面冷却 / ピット炉・スラブヤード） |
| `M` | メニュー（サイドバー）を畳む / 開く |

マウス：左ドラッグ回転 / 右ドラッグ平行移動 / ホイール拡大縮小

サイドバーは **ブランド → 主操作（開始/中止・一時停止・リセット）→ 4 つのタブ（準備／運転／表示／設備）→
タブの中身** の固定構造です。準備タブは作業の流れ順（① 素材と目標 → ② パススケジュール）、運転タブは
運転モードと板反り対策、表示タブは断面・描画品質・凡例・演出・ショートカット、設備タブは諸元とロール現品・
テーブル区分です。タブの下段に要約（材質と目標厚／モードと倍率／断面と品質／ロール状態）が出るので、
開かなくても今の値が読めます。**主操作とタブの位置は、状態やメッセージの長さ、タブの切替で動きません。**
「今どうなっていて、次に何をするか」の状態文と一時通知は、サイドバーではなく**計器バーの真上の状態行**
（高さ固定・1 行）に出ます。運転中に頻繁に使う視点・断面・注記・実績は画面上部のツールバー 1 行にあり、
視点は短い名前とキー番号の帯（`1`〜`9`・`0`）です。

素材パネルでは **材質（7 合金）・呼び厚・面削量・幅・長さ・炉出し温度・目標板厚（4〜150 mm）・
トリム量** を設定します。待機中の変更は即座にパススケジュールへ反映され、仕上げ形態
（コイル / 板材）と使う設備（75 mm シャーの要否）が併記されます。運転中の変更は
「適用してリセット」で反映します。計器バーには材料温度の上/芯/下と反り半径（端の浮き・
上下温度差）を出しています。
